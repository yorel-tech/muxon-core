Who Generates the Private Key?
You generate it yourself - The SSH private key is NOT generated by Infron or Libvirt. You create it using standard SSH tools:

# Generate a new SSH key pair
ssh-keygen -t ed25519 -b 4096 -C "infron@libvirt-host" -f ~/.ssh/libvirt_key

# This creates:
#  ~/.ssh/libvirt_key      (PRIVATE - keep secret!)
#  ~/.ssh/libvirt_key.pub  (PUBLIC - give to server)

How to Set Up on Libvirt Server
# 1. Copy public key to the libvirt server
ssh-copy-id -i ~/.ssh/libvirt_key.pub root@libvirt-server

# Or manually add to authorized_keys
cat ~/.ssh/libvirt_key.pub | ssh root@libvirt-server "cat >> ~/.ssh/authorized_keys"

How Infron Uses the Private Key
When you register a LIBVIRT provider, Infron stores the private key in the database (encrypted at rest):

┌─────────────────────────────────────────────────────────────────────┐
│                  Infron Database Storage                       │
├─────────────────────────────────────────────────────────────────────────┤
│ Provider Entity:                                               │
│ {                                                            │
│   "id": "uuid-1234",                                       │
│   "type": "LIBVIRT",                                       │
│   "endpoint": "ssh://root@192.168.1.100:22",        │
│   "credentials": {                                            │
│     "sshPrivateKey": "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----"  │
│   },                                                         │
│   ...                                                          │
│ }                                                            │
└─────────────────────────────────────────────────────────────────────────────┘

When Infron needs to manage VMs on the libvirt server:

┌─────────────────────────────────────────────────────────────────────┐
│              VM Creation Flow                                │
├─────────────────────────────────────────────────────────────────────────┤
│                                                              │
│  1. Infron retrieves private key from DB (decrypted)          │
│                                                              │
│  2. Creates SSH connection: ssh://root@host:22           │
│     • Uses the private key for authentication                  │
│     • No password prompt needed!                                │
│                                                              │
│  3. Sends libvirt commands via SSH:                         │
│     • virsh define <domain.xml>                              │
│     • virsh start <domain-name>                                │
│     • virsh list --all                                      │
│                                                              │
│  4. Returns VM status to Infron                                │
│                                                              │
└─────────────────────────────────────────────────────────────────────────────┘

Key Security Points
Aspect	Details
Private key never leaves Infron	Stored encrypted in database, only decrypted in memory when needed
Public key on libvirt server	Only the public key (id_rsa.pub) is stored on the server
Passphrase protection	Optional - if set, the private key is encrypted and requires passphrase to decrypt
One key per provider	Each libvirt server can have its own SSH key pair
Example: Complete Flow
# Step 1: Generate SSH key pair (you do this)
ssh-keygen -t ed25519 -f ~/.ssh/libvirt_prod -C "infron-prod"

# Step 2: Add public key to libvirt server (you do this once)
ssh-copy-id -i ~/.ssh/libvirt_prod.pub root@192.168.1.100

# Step 3: Register provider in Infron (API call)
curl -X POST http://localhost:8080/api/v1/providers \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{
    "name": "libvirt-prod",
    "type": "LIBVIRT",
    "endpoint": "ssh://root@192.168.1.100:22",
    "credentials": {
      "sshPrivateKey": "'"$(cat ~/.ssh/libvirt_prod)"'"
    }
  }'

# Step 4: Infron can now manage VMs on that server
# The private key is used for SSH authentication automatically

Summary
You generate the SSH key pair using ssh-keygen (or PuTTYgen on Windows)
Public key goes to the libvirt server's ~/.ssh/authorized_keys file
Private key is registered with Infron via the API
Infron uses the private key to authenticate via SSH when managing VMs
No password is needed after initial setup

## Local QEMU/Libvirt (no SSH)

For development or when Libvirt runs on the same host as Infron, use the **direct socket** URI so no SSH or SSH server is required.

**Error you avoid:**  
`Cannot recv data: ssh: connect to host 127.0.0.1 port 22: Connection refused`  
That happens when the app uses `qemu+ssh://user@127.0.0.1/system` but no SSH server is listening.

**Fix:** Use the local Libvirt URI via **node** credentials.

1. Create the Libvirt provider as usual (endpoint can be e.g. `libvirt://localhost`). The API still requires provider credentials to include `sshPrivateKey`; for local-only you can use any placeholder (e.g. a minimal PEM string) since the node’s `uri` will be used instead of SSH.
2. When creating the **node** for that provider, set node credentials to use the direct URI:

   ```json
   {
     "uri": "qemu:///system"
   }
   ```

   If the node already exists, update it so its credentials include `"uri": "qemu:///system"`.

Infron will then connect with `qemu:///system` (Unix socket to local libvirtd) instead of `qemu+ssh://user@host/system`.

## Debugging local QEMU/Libvirt

### 1. Check libvirtd is running

```bash
sudo systemctl status libvirtd
# or
sudo systemctl status libvirt
```

Start if needed:

```bash
sudo systemctl start libvirtd
```

### 2. Test connection with virsh

```bash
virsh -c qemu:///system list --all
```

If this works, the same URI will work from Infron (with node credentials `{"uri": "qemu:///system"}`).

### 3. Permission / group

Your process (e.g. the user running the Infron app) must be in the `libvirt` group to use the default socket:

```bash
groups
# add if missing:
sudo usermod -aG libvirt $USER
# then log out and back in (or new shell)
```

### 4. KVM availability (for full virtualization)

```bash
# Optional: check KVM module
lsmod | grep kvm
# Optional: /dev/kvm present
ls -la /dev/kvm
```

### 5. What Infron uses

- **Remote:** node credentials `host` + `user` → URI `qemu+ssh://user@host/system` (requires SSH on the host).
- **Local:** node credentials `uri` → that value used as-is (e.g. `qemu:///system`). No SSH.
